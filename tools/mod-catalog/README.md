# Статический каталог модов

Клиент получает `mods.json` с `raw.githubusercontent.com`, а не опрашивает
GitHub API. Поля: `schemaVersion: 1`, `revision` — полный SHA исходного коммита,
`files` — полный список `{path, size, sha}` для `.pak` и `.sig`.
Файлы скачиваются по исходному коммиту; хеши — Git blob SHA-1.

`update-mod-catalog.yml` предназначен для установки в репозитории модов по пути
`.github/workflows/update-mod-catalog.yml`. Он запускается после изменения модов
или вручную, получает дерево с временным `GITHUB_TOKEN` и записывает каталог
в `main`. Для этого требуется разрешение `contents: write`. Клиентам токен не
передаётся. Пустое/неполное дерево и повторяющиеся имена не публикуются.

Без установленного workflow администратор может обновить каталог вручную
после изменения модов (нужен GitHub CLI с доступом на запись в репозиторий):

```powershell
./tools/mod-catalog/Publish-ModCatalog.ps1
```

После установки workflow проверьте успешный запуск в Actions и поле `revision`
в опубликованном `mods.json`. Автоматизация не считается настроенной, пока
workflow не установлен и его первый запуск не завершился успешно.
