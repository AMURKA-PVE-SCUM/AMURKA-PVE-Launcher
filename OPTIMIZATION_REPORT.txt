1. ПЕРЕХОД НА .NET 10 И C# 14
--------------------------------------------------------------------------------
* Проектный файл (AmurkaLauncher.csproj):
  - TargetFramework обновлен с net8.0-windows на net10.0-windows.
  - Установлен параметр <LangVersion>14.0</LangVersion>.
* Использование возможностей C# 14:
  - Semi-Auto Properties (ключевое слово 'field'):
    В модели ModCategory.cs устранены ручные backing fields (_isSelected,
    _totalCount, _installedCount). Свойства теперь используют контекстное
    слово 'field' внутри аксессоров, сохраняя вызовы INotifyPropertyChanged:
      public bool IsSelected {
          get;
          set {
              if (field != value) {
                  field = value;
                  OnPropertyChanged();
              }
          }
      }
  - Коллекционные выражения (Collection Expressions) и Spread-оператор ([.. list]).
  - Генераторы регулярных выражений ([GeneratedRegex]) на этапе компиляции.
  - Span-слайсинг и работа со срезами памяти (ReadOnlySpan<char>) без аллокаций.
  - Использование ref / ref readonly структур для исключения копирования в памяти.


2. УСТРАНЕНИЕ УТЕЧЕК ПАМЯТИ И СИСТЕМНЫХ РЕСУРСОВ
--------------------------------------------------------------------------------
1) Критическая нагрузка на сборщик мусора (GC Thrashing) в ParticleCanvas.cs:
   - Проблема:
     Каждый кадр рендеринга (60–144 FPS) для 80 частиц создавалось от 80 до 160
     новых объектов SolidColorBrush. Это приводило к выделению тысяч временных
     объектов в секунду и регулярным микрофризам из-за работы Gen0 GC.
   - Решение:
     Создан массив из 256 предварительно сгенерированных и замороженных
     кистей (CachedBrushes) под все уровни альфа-канала (0..255).
     Аллокации кистей в цикле рендеринга сведены к 0 байт.
   - Particle преобразован из ссылочного класса (class) в структуру (struct),
     массив частиц предварительно аллоцирован, работа ведется по ссылке
     (ref var p = ref _particles[i]).
   - Добавлено отключение подписки на CompositionTarget.Rendering при
     скрытии (IsVisible = false) или выгрузке элемента из дерева WPF.

2) Утечка дескрипторов сокетов (Socket Exhaustion) в UpdateService.cs:
   - Проблема:
     При проверке обновлений методом отслеживания редиректа создавался новый
     экземпляр HttpClient с HttpClientHandler. При периодических проверках сокеты
     оставались в состоянии TIME_WAIT, что приводило к исчерпанию системных
     портов и сетевым ошибкам.
   - Решение:
     Реализованы единые статические экземпляры HttpClient и RedirectClient
     на базе SocketsHttpHandler с контролем времени жизни соединений в пуле
     (PooledConnectionLifetime = 15 мин).

3) Утечка дискового пространства в LauncherVerificationService.cs:
   - Проблема:
     Лог верификации (verification.log) каждые 2 минуты дописывался без ограничений
     по размеру, что в течение длительной работы приводило к бесконечному росту файла.
   - Решение:
     Внедрена автоматическая ротация: при достижении размера 1 МБ текущий лог
     переименовывается в .old, а новый лог создается с чистого листа.

4) Утечка ресурсов таймеров и Discord RPC при выходе (MainWindow.xaml.cs):
   - Проблема:
     Таймер всплывающих уведомлений (_toastTimer) не останавливался при закрытии,
     а DiscordRpcService не имел строгой очистки состояния.
   - Решение:
     В MainWindow_Closing гарантированно останавливаются все три таймера:
     _updateCheckTimer, _verificationTimer, _toastTimer.
     В DiscordRpcService.cs внедрен безопасный паттерн IDisposable с обнулением
     клиента и подавлением финализатора (GC.SuppressFinalize).


3. ОПТИМИЗАЦИЯ ПРОИЗВОДИТЕЛЬНОСТИ И ВЫДЕЛЕНИЯ ПАМЯТИ
--------------------------------------------------------------------------------
1) Пул массивов (ArrayPool<byte>) при скачивании файлов:
   - В UpdateService.cs и ModManagerService.cs буферы размером 80 КБ (81920 байт)
     больше не создаются в управляемой куче (что создавало риск фрагментации
     Large Object Heap). Буфер арендуется из ArrayPool<byte>.Shared и возвращается
     в блоке finally.

2) Безопасный Lock-Free трекинг скачивания модов (ModManagerService.cs):
   - Устранен lock и вызов fileBytes.Values.Sum() на каждом прочитанном блоке.
   - Подсчет скачанных байтов переведен на атомарный Interlocked.Add.
   - Обновление прогресс-бара UI переведено на асинхронный Dispatcher.BeginInvoke,
     что исключило микрозадержки рабочих потоков скачивания.

3) Генераторы регулярных выражений ([GeneratedRegex]):
   - В UpdateService.cs, LauncherVerificationService.cs и ScumDetectionService.cs
     все регулярные выражения переведены на статические методы с [GeneratedRegex].
     Код парсинга генерируется во время компиляции, устраняя рантайм-компиляцию
     и связанные с ней аллокации.

4) Безаллокационное сравнение версий:
   - Метод IsNewerVersion переписан с использованием Version.TryParse и
     ReadOnlySpan<char> без создания массивов через Split('.') и LINQ.

5) Кэширование кистей интерфейса:
   - В MainWindow.xaml.cs цвета кнопок и плашек категорий вынесены в статические
     замороженные кисти (CreateFrozenBrush), что исключило создание объектов
     SolidColorBrush при кликах и фильтрации.
